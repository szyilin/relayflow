## Context

工作台 `/app/messages` 会话列表已支持未读数、`mention_unread`、进入会话后的已读上报，以及消息尾部拉取（`GET /app-api/im/message/list?afterSeq=`）。成员表 `im_conversation_member` 已有 `read_seq`、`unread_count`、`pinned`（默认 0），但 **置顶未接线**；列表红点与对端可见回执共用 `read_seq`，无法表达「只清我侧红点 / 强制标未读」。

Agent 侧 `ImConversationReadApi` 已具备 `aroundSeq` / `beforeSeq` 窗口读，可对齐到用户端消息列表契约。

本 change 仍处于 **想法收集期**：用户将继续补充右键能力等需求；实现须等用户明确收口后再按 tasks 执行。

## Goals / Non-Goals

**Goals:**

1. 会话级置顶 + 置顶区折叠与折叠态未读聚合。
2. 列表 inbox 态与对端 `read_seq` 回执分离（标记已读/未读）。
3. 进入会话即推进真实已读；打开未读会话自动定位首条未读 + 分界线。
4. 超大历史/未读量下的 seq 窗口加载与「回到最新」假滑动真窗口。
5. 会话旗标（右键开关；列表标题行右侧 + 聊天标题名后展示；分组「标记」筛选）。
6. 会话列表行版式：身份类型标签在用户名后；头像相对双行文本垂直居中。
7. 用户私有会话标签：右键打标/新建；分组栏「标签」下按标签筛选（会话行不强制展示标签文案）。
8. 消息免打扰：弱未读小红点 + 静音铃铛；汇总角标不计免打扰未读；分组「免打扰」筛选。
9. 消息侧分组栏（九类）+ 编辑分组（展示/隐藏/排序，默认全展示）。

**Non-Goals:**

- 不为每条消息存每用户已读行（主路径）。
- 不重做气泡内「对方已读勾」语义（仍读成员 `read_seq`）。
- 本批不做移除会话 / 归档；不做云文档 / 话题 / 已完成等业务分组。
- 不做复杂「按时段免打扰」调度（V1 右键开关即可）。
- 不做「标记未读恢复历史未读条数」；固定露出 1 条。
- 自定义标签本批不上会话列表行（侧栏筛选即可）。


## Decisions

### D1. 双水位：`read_seq`（回执）与 `badge_seq`（列表红点）

```
                    ┌─────────────────────────────────────┐
  新消息 seq↑       │  im_conversation_member             │
                    │  read_seq   → 对端可见已读回执      │
                    │  badge_seq  → 我侧列表红点水位      │
                    │  unread_count = count(seq>badge_seq)│
                    └─────────────────────────────────────┘
```

| 操作 | `badge_seq` | `read_seq` | `read.updated` fanout |
|------|-------------|------------|------------------------|
| 进入会话（面板激活） | → 当时 max seq | → 当时 max seq | 是（read_seq 提升时） |
| 停留期间新消息到达且会话仍为前台活动会话 | → 新 max | → 新 max | 是 |
| 列表「标记已读」且未打开 | → max seq | **不变** | 否 |
| 列表「标记未读」 | → `max_seq - 1`（固定露出 **1** 条；max_seq=0 则 no-op） | **不变** | 否 |

**标记未读细则（已拍板：固定 1 条）：**

- 一律设 `badge_seq = max_seq - 1`（若会话尚无消息则 no-op），列表 `unreadCount = 1`。
- 若本来已有未读（无论 5 还是 50）：标记未读后也收敛为 **1**（不恢复历史未读数）。
- `read_seq` 不动，对端回执不变。

**为何不用「每消息每用户状态表」：** 会话消息可达万级，成员数 × 消息数爆炸；成熟 IM 普遍用单调水位。气泡已读勾只需对端 `read_seq` 比较消息 `seq`。

**为何不用单一 boolean `marked_unread`：** 无法正确叠加「标记已读后新消息又来」；独立 `badge_seq` 与计数公式自然兼容。

**字段命名：** 实现可用 `badge_seq`；列表 VO 继续返回 `unreadCount`（由 badge 推导），另返回 `readSeq`（已有或补齐）供客户端区分。迁移时 `badge_seq` 初始 = 现有 `read_seq`。

### D2. 真实已读推进时机（行业惯例定案）

与现行 im 规格中「不得仅在打开时立刻标到 max、须按可视区域」的表述冲突；本 change **改为工作台策略**：打开会话即视为真实阅读（不要求滚完未读气泡）。

**定案：进入推进 + 停留续报**（不对「离开」做必选 flush）：

1. **进入（主路径）**：会话消息主面板成为当前活动会话时，将 `read_seq` 与 `badge_seq` 推进到**当时**会话 max seq，并 fanout `read.updated`（若有提升）。请求成功落库后即扛断电/杀进程。
2. **停留续报**：该会话保持前台活动期间，新消息到达则继续上抬两水位到新的 max（可对上报做短防抖，但权威仍是服务端水位）。

**刻意不做「离开必 flush」：** 正常切会话时，停留续报通常已覆盖；断电/强杀本来就没有可靠 leave 钩子，把正确性绑在 leave 上反而制造假安全感。若极端竞态漏报一两秒内的新消息，**下次再进入该会话**会再次推进并纠正——可接受。

**不采用「仅离开时才报」：** 对端已读反馈应在打开后尽快发生。  
**不采用「必须滚完可视区才报」：** 与工作台意图冲突，万级未读下不可用。

误点开也会推进回执——行业默认代价；我侧可用「标记未读」拉回红点（对端回执不回退）。

### D2b. 其它合理默认（一并收口）

- **无 inbox 未读进入**：视口停在最新（底部），保持现状。
- **`unread_count`**：继续在成员行上**物化**（由 `badge_seq` 推导后写入），保证会话列表查询性能；不以每次列表实时 `COUNT(*)` 为唯一来源。

### D3. 置顶：复用 `pinned` + `pinned_at`；折叠态多端同步

- `pinned`：0/1（已有）。
- 新增 `pinned_at`（TIMESTAMPTZ，可空）：置顶时写入，取消清空；列表排序：`pinned DESC, pinned_at DESC NULLS LAST, last_msg_time DESC`。
- API：`POST /app-api/im/conversation/pin` `{ conversationId, pinned: boolean }`。
- 仅影响当前用户成员行，不影响他人。

**折叠（已拍板：要多端同步）：** 经既有用户偏好（C 类读合并 / 写 upsert）持久化，例如 `settings.im.pinnedSectionCollapsed`（boolean，默认 `false`）。切换折叠时 PUT preference；登录/切租户后 GET 水合。折叠横条展示置顶会话数与 **聚合 unreadCount / mention**。localStorage 至多作瞬时缓存，**不得**作跨设备权威。

**视觉：** 置顶行相对普通项略降对比度/略深底（用既有 `--ws-*` token）；折叠横条为可点击一行。

### D4. 消息窗口加载（对齐 Agent around 读）

扩展用户端列表契约（形状可微调，以实现 contract 为准）：

| 模式 | 参数 | 行为 |
|------|------|------|
| 最新窗 | `limit`（默认 ~50，硬上限） | 取最大 seq 一侧 |
| 向后增量 | `afterSeq` + `limit` | 现有语义，加 limit |
| 向前历史 | `beforeSeq` + `limit` | seq < beforeSeq |
| 锚点窗 | `aroundSeq` + `before` + `after` | 首条未读定位 |

打开未读会话：

1. `firstUnreadSeq = badge_seq + 1`（进入前快照）。
2. `aroundSeq=firstUnreadSeq` 拉上下窗口。
3. 滚动定位到该条；其上渲染「以下为新消息」分界。
4. 上滑 `beforeSeq`、下滑 `afterSeq` 续载；合并去重按 seq。

「回到最新 / 滑到最底」：

- **禁止**循环拉取中间全部空洞。
- 直接请求最新窗，替换或拼接策略：若中间缺口过大，丢弃中间空洞段，只保留最新窗 +（可选）当前锚点窗两段，中间用「加载更早消息」隐式衔接或跳转时重置为单窗。
- 动画：前端假滑动/短过渡即可，不假装已插入中间数千条 DOM。

下方未读提示：进入时快照 `enterUnreadCount`；若视口未贴底，FAB/横条显示剩余未读（可随滚动减少）。

### D5. 会话列表右键菜单（本批范围）

新增会话级上下文菜单（与消息气泡右键分离）。**本批**：置顶/取消置顶、标记已读、标记未读、旗标/取消旗标、消息免打扰/取消、**标签**（二级子菜单）。移除会话等 **先不做**。

### D5b. 旗标（成员私有标记）


- 成员行新增 `flagged`（SMALLINT 0/1，默认 0）；仅当前用户成员行，多端随成员数据同步（非 preference）。
- API：`POST /app-api/im/conversation/flag` `{ conversationId, flagged: boolean }`（路径可微调）。
- **列表**：标题行（用户名所在行）最右侧展示小旗帜图标（与时间戳同一行时：旗帜在时间左侧或按参考稿置最右；实现时保证「名称行最右侧有旗、不挤占预览行」）。未旗标不占位或占透明位由 UI 定，但不得误显示为已旗标。
- **聊天头**：活动会话标题中，显示名之后紧跟同一旗帜（有旗才显示）。
- 本批不做按旗筛选；字段预留后续能力。

### D5c. 列表行版式（身份类型标签，非用户自定义标签）

当前实现把「群 / 助手」等**身份类型**标签放在 **预览文案前**，头像用默认 flex 顶对齐，略偏上。改为：

```
[ Avatar ]  Title  [身份类型标签…]     [旗?] [时间]
  (居中)   Preview / [有人@我] …      [静音铃?] 或 未读提示
```

- **身份类型标签**（群、助手、机器人、智能体、官方等）：MUST 紧跟用户名之后（同一标题行），MUST NOT 放在预览行开头。`[有人@我]` 等消息态提示仍可留在预览行。
- **头像**：相对右侧「标题行 + 预览行」文本块垂直居中，避免顶对齐偏上。
- **右侧状态列**（参考常见 IM）：标题行右侧可放旗标；预览行右侧可放静音铃铛；未读提示与铃铛/数字角标互斥规则见 D5e。与 D5d **用户自定义标签**区分：本批自定义标签不上列表行。

### D5d. 用户自定义会话标签（右键打标 + 分组栏筛选）

「邮件可选择」按产品意图理解为 **二级（级联）子菜单**：主菜单「标签」项悬停/展开后，旁侧（或嵌套）列出可选标签。

**数据（当前用户私有，租户内）：**

| 概念 | 建议表（名可微调） | 说明 |
|------|-------------------|------|
| 标签库 | `im_user_tag`（`tenant_id, user_id, name, …`） | 用户历史标签；同用户下 name 唯一（大小写规则实现时定，倾向 trim 后唯一） |
| 打标关联 | `im_conversation_user_tag`（`tenant_id, user_id, conversation_id, tag_id`） | 该用户给某会话打上的标签；唯一约束防重复 |

**交互：**

1. 右键会话 → 「标签」→ 二级面板列出该用户标签库（按最近使用或名称序，实现选定一种稳定序）。
2. 点选已有标签 → 幂等打到该会话（已存在则保持）。
3. 历史标签过多 → 二级列表区域 **限高 + 滚动**；底部固定「添加新标签」（不随列表滚走，或滚到底仍可见——优先吸底固定）。
4. 「添加新标签」→ 输入名称 → 写入标签库并打到当前会话；空名/超长拒绝。
5. **本批**：会话列表行 / 聊天标题 **不强制**展示自定义标签文案；筛选用消息侧分组「标签」子项（见 D7）。不要求完整卸标 UI（后续可补）。API 须支持标签库与会话已打标签查询。

**API 草案（路径可微调）：** 标签库 list；创建 tag；assign tag to conversation（create+assign 可合并）。均 scoped 当前 JWT 用户。

### D5e. 消息免打扰（mute）

成员表已有 `mute_until`（可空）。V1 右键开关：

- **开启免打扰**：写入 `mute_until` 为足够远的未来时间（或实现约定的「长期免打扰」哨兵）；列表 VO 暴露 `muted: true`（由 `mute_until > now` 推导即可）。
- **取消**：`mute_until = null`。
- 本批不要求「静音到今晚」等时段 UI；字段保留扩展能力。

**列表未读展示（常见 IM 惯例）：**

| 状态 | 有 inbox 未读时 |
|------|----------------|
| 未免打扰 | 醒目未读数字角标（现有大红点/数字） |
| 已免打扰 | **不**显示数字大红点；仅显示**不显眼的小红点**（无数字或极弱提示） |
| 已免打扰且无未读 | 无红点；仍可显示静音铃铛 |

**静音铃铛：** 免打扰会话在列表行展示静音小铃铛（划掉铃铛或等价图标），建议与预览行右侧对齐、位于旗标下方（见参考稿）；未免打扰不显示。

**导航/全局未读汇总：** 工作台消息入口等醒目未读角标 MUST NOT 将免打扰会话的 `unreadCount` 计入（或等价：汇总只含非 mute 会话）。会话仍保留真实 `unreadCount` 供进会话与小红点判断。

**通知：** 若后续有桌面/推送，免打扰会话 MUST 不打断（本批若尚无推送，至少在列表与汇总行为上对齐）。`@我` 是否在免打扰下仍强提示：本批 MAY 保留预览行 `[有人@我]` 文案，但未读角标仍走弱红点；不强行做例外大红点。

### D6. 交付切片（顺序强制）

前端优先纵向切片，**实现时不得跳步**（尤其不得在置顶/旗标/免打扰/inbox/标签未就绪前先做分组栏）：

1. `-web` 列表行版式（身份标签位置、头像居中）
2. `-web` 置顶 + 旗标 + 免打扰（含折叠、弱红点、铃铛）
3. `-web` inbox 标记已读/未读 + 自定义标签打标（二级菜单）
4. `-web` 消息侧分组栏 + 编辑分组（依赖上列成员态字段）
5. `-web` 未读定位 + 窗口加载 + contract 收齐
6. `-api` 双水位 / pin / flag / mute / tag / 偏好 / 窗口 list
7. `-integrate` 去临时数据联调

**开干条件：** 用户明确要求按本 change 的 `tasks.md` 实现（如 `/opsx:apply`）。想法收集期与「只改 OpenSpec」期间 **禁止** 写业务代码。


### D7. 消息侧分组栏（本版九类）

在 `/app/messages` 会话列表左侧（或等价位置）增加 **分组** 栏，标题旁齿轮进入「编辑分组」。

**内置分组 id 与筛选（客户端过滤为主；列表数据须带齐判定字段）：**

| id | 文案 | 筛选 |
|----|------|------|
| `all` | 消息 | 全部会话 |
| `unread` | 未读 | `unreadCount > 0` |
| `flagged` | 标记 | `flagged` |
| `mention_me` | @我 | 未读且 `mentionedMe` / `mention_unread`（已读清 mention 后离开本分组） |
| `tags` | 标签 | 父级：仅展开/收起，**不可单独作为筛选结果**；子项为用户标签库中的每个标签 |
| `tag:{tagId}` | （标签名） | 当前用户打了该标签的会话（不区分已读） |
| `direct` | 单聊 | `type === direct` |
| `group` | 群聊 | `type === group` |
| `muted` | 免打扰 | 免打扰中 |
| `bot` | 机器人 | `type === bot_dm`（及产品认定的机器人会话） |

**标签区交互：** 可折叠；旁侧「+」可 **新建标签**（写入标签库，不必立刻绑会话）；点具体标签才过滤会话列表。标记分组上可显示旗标数量等次要计数（可选，有则与参考稿类似）。

**编辑分组弹层：** 「展示 / 隐藏」两区；展示区可拖拽排序、点减号移入隐藏；隐藏区点加号移回展示。**默认九类内置分组全部在展示区**（`tags` 作为一项；具体用户标签不进编辑列表，随标签库变化挂在「标签」下）。本版不提供云文档/话题/已完成项。

**偏好：** `settings.im.sidebarGroupOrder`（展示区有序 id 列表）+ `settings.im.sidebarGroupHidden`（隐藏 id 列表），或等价单一结构；C 类合并；多端同步。非法 id 丢弃；空展示列表回退到产品默认全开顺序。

**空态：** 某分组下无会话时，会话列表区用统一空状态文案（可按分组微调）。

## Risks / Trade-offs

- [进入即已读偏粗] → 接受产品权衡；若日后要「仅可视已读」，可再加精细模式而不改双水位模型。
- [标记未读与回执不一致，对端仍显示已读] → 预期行为；UI 文案勿暗示「对方会看到你标未读」。
- [窗口跳跃导致中间消息暂缺] → 搜索/引用跳转需复用 around 加载；引用已有 UX 可后续加强。
- [unread_count 改由 badge_seq 计算] → 所有写路径（发消息递增、标记、进入）必须统一，避免双计数源漂移。
- [偏好 PUT 失败] → 折叠 UI 可乐观更新并提示失败回滚；与既有 preference store 错误暴露一致。

## Migration Plan

1. Flyway：`im_conversation_member` 增加 `badge_seq`、`pinned_at`、`flagged`；`UPDATE badge_seq = read_seq`。
2. Flyway：新增 `im_user_tag`、`im_conversation_user_tag`（或等价命名）及唯一索引。
3. 用户偏好：`settings.im.pinnedSectionCollapsed`、分组栏 order/hidden 并入 GET/PUT 合并默认（无行不预插，C 类）。
4. 发消息/推送路径：未读递增改为相对 `badge_seq`；`read.updated` 仍只跟 `read_seq`。
5. 列表 VO：返回 `pinned`、`pinnedAt`、`flagged`、`muted`（或 `muteUntil`）、`unreadCount`、`readSeq`（自定义标签本批可不进列表 VO）。
6. 回滚：新列/表可留存；客户端忽略新字段即弱化行为。
