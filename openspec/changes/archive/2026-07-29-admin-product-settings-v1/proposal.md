## Why

工作台已交付即时消息、云文档、日历等产品能力，但管理后台缺少「企业级产品设置」入口：管理员无法统一管控群规模、群权限、消息撤回/编辑等组织策略。飞书将此类设置收敛在「产品设置」下按产品分栏；RelayFlow 需要同等的组织面配置，并与用户头像菜单里的个人偏好（仅影响本人体验）明确分层。

## What Changes

- **管理端新增「产品设置」板块**：类飞书的产品入口（mega menu / 产品列表），第一版仅规划并露出 **云文档、即时消息、日历** 三个产品；点击进入该产品的组织级设置壳层。
- **产品图标统一注册表**：工作台导航、产品设置入口、面包屑等共用同一套产品图标定义；换图标只改注册表一处。
- **即时消息 · 组织设置（本母 change 详规，优先实现）**
  - **群规模管控**（仅对话群）：企业默认人数上限（预设 5/10/30/50 + 自定义，默认 50）；**用户规则集**（部门/用户 → 可发起群聊人数上限）；**群组规则集**（本企业群 → 该群人数上限）。
  - **群权限管控**：公开群可搜可加开关；部门群成员退出策略；群成员信息导出策略（对齐飞书文案与选项语义）。
  - **消息权限管控**：撤回 / 编辑开关 + 时间窗（对齐飞书）。
  - **群组管理**：本版 **不做**。
- **配套工作台能力补齐**：上述设置所依赖、但当前缺失的客户端/服务端能力一并纳入路线图（人数上限强制、公开群、部门群与退群策略、成员导出、消息撤回与编辑等）。
- **云文档 / 日历 · 组织设置**：本母 change **仅占位**（入口可见 + 空态/「即将开放」），不写详细设置项与开发文档；待 IM 完成后另开 change 详规。
- **分层边界**：个人偏好（`user-preference` / 头像设置）继续只影响当前企业下该用户体验；产品设置只影响 **当前组织对产品的整体策略与管理能力**。

## Capabilities

### New Capabilities

- `admin-product-settings`: 管理端产品设置壳层（入口、产品目录、图标注册、按产品子路由）；含云文档/日历占位页与 IM 设置导航骨架。

### Modified Capabilities

- `im`: 增加租户级 IM 组织策略（群规模/群权限/消息权限）的持久化、Admin API、以及工作台侧强制执行与配套能力（撤回、编辑、公开群、部门群退出、成员导出等）。
- `web-admin`: 管理端导航与路由增加「产品设置」及 IM 子页；权限码门禁。
- `docs`: **占位** — 仅声明「组织级云文档设置」能力预留，不展开具体设置项。
- `calendar`: **占位** — 仅声明「组织级日历设置」能力预留，不展开具体设置项。

## Impact

| 区域 | 影响 |
|------|------|
| `web/` | 管理端产品设置壳层与 IM 三页 UI；产品图标注册表；工作台 IM（建群上限、公开群、撤回/编辑等） |
| `relayflow-module-im-*` | 租户策略表、Admin API、建群/加成员/退群/消息写路径强制执行；撤回/编辑等新 API |
| `relayflow-module-system-*`（可能） | 部门/用户选择器复用；权限种子；若部门群依赖组织模型则扩展 |
| `relayflow-module-docs-*` / `calendar-*` | 本母 change **不改业务**；仅前端占位路由 |
| Flyway | `im_` 前缀策略表 / 规则表；群与消息表可能增列（公开、上限覆盖、撤回/编辑元数据等） |
| 回滚 | 新表可空迁移；策略默认对齐「50 人 / 允许公开 / 允许撤回与编辑 24h」等安全默认，关闭开关即可降级行为 |
| 交付形态 | **母 change 路线图**；实际编码按子 change（`-web` → `-api` → `-integrate`）分批，单次会话不一次做完 |
