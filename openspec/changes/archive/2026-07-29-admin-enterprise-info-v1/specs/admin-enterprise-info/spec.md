## ADDED Requirements

### Requirement: 管理端企业信息页

系统 SHALL 在管理后台提供「企业信息」页面（路由以 `/admin` 为前缀），包含两个 Tab：**企业信息管理** 与 **企业地址管理**。页面 MUST 遵循现有管理端壳层与权限门禁。

#### Scenario: 侧栏进入

- **WHEN** 具备企业信息查询权限的管理员打开管理后台
- **THEN** 导航中可见「企业信息」（或「企业设置 > 企业信息」）入口
- **AND** 进入后默认展示企业信息管理 Tab

### Requirement: 企业信息字段与只读企业编号

企业信息管理 MUST 展示并允许编辑约定的企业档案字段；企业编号 MUST 展示当前租户 `code` 且不可编辑。MUST NOT 在本版本实现企业域名编辑或注销/解散企业。

#### Scenario: 企业编号只读

- **WHEN** 管理员查看或编辑企业信息
- **THEN** 企业编号字段为只读，值为创建企业时生成的编号
- **AND** 保存请求即使携带编号变更也被忽略或拒绝

#### Scenario: 注册可回填字段

- **WHEN** 企业由注册创建且创建人资料含可用的联系人信息
- **THEN** 企业信息页中对应联系人字段已预填（若注册流程已写入）
- **AND** 未在注册采集的字段（如行业、规模）可为空并在本页编辑

#### Scenario: 保存企业信息

- **WHEN** 管理员修改允许编辑的字段并保存
- **THEN** 当前租户企业档案被更新
- **AND** 企业编号与域名相关能力保持不变（域名功能不存在）

### Requirement: 企业地址管理

企业地址管理 Tab MUST 支持地址列表（搜索/筛选可选）、新增、编辑、启停。地址类型 MUST 支持多选，选项至少为：职位地址、面试地址、门店地址。行政区划 MUST 使用中国四级级联（数据来自平台 geo）；详细地址为文本输入。MUST NOT 要求地图选点。

#### Scenario: 新增多类型地址

- **WHEN** 管理员新增地址并选择多个地址类型、完整中国级联与详细地址后确认
- **THEN** 列表出现该地址，展示类型标签、区划路径与状态

#### Scenario: 停用地址

- **WHEN** 管理员对已启用地址执行停用
- **THEN** 该地址状态变为停用且仍可在列表中按状态筛选查看（若提供状态筛选）

### Requirement: 企业信息管理端 API 与权限

系统 SHALL 提供 `/admin-api/system/` 下企业信息与地址的 REST API，并使用 permission code 保护；无权限用户 MUST 无法读写。

#### Scenario: 无权限拒绝

- **WHEN** 已登录但缺少企业信息相关 permission 的用户调用企业信息更新 API
- **THEN** 系统返回权限拒绝（如 403）
- **AND** 数据未被修改
